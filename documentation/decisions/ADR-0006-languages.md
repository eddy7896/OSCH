# ADR-0006: Languages, right-to-left and fonts

- **Status:** Accepted (2026-10-15, owner instruction: English primary; support Urdu and other right-to-left languages, Hindi and other major regional languages)
- **Resolves:** DS-2 in `design_system_spec.md`; audit finding D2

## Decisions
1. **English is the primary language** and the default everywhere. Changing language is an **explicit choice** (URL, user preference, school default); the browser's `Accept-Language` and the phone's language are **never** used to switch automatically.
2. **Supported languages (19), single source `packages/i18n/locales.json`:**
   - **Right-to-left (6):** Urdu `ur`, Kashmiri `ks`, Sindhi `sd`, Pashto `ps`, Persian `fa`, Arabic `ar`.
   - **Left-to-right regional (12):** Hindi `hi`, Bengali `bn`, Assamese `as`, Marathi `mr`, Dogri `doi`, Gujarati `gu`, Punjabi (Gurmukhi) `pa`, Odia `or`, Tamil `ta`, Telugu `te`, Kannada `kn`, Malayalam `ml`.
   - **Tiers:** `primary` = English. `ready` = complete draft catalog + fonts + direction verified end to end: **Hindi and Urdu**. `supported` = fonts, direction and formatting work; the UI shows English per missing key until translated (all others). Adding a language = one entry in `locales.json` plus its messages.
3. **Nothing non-English ships to schools until a native speaker reviews it.** The Hindi and Urdu catalogs are **machine-quality drafts** written to prove the pipeline; `messages/status.json` marks every language `reviewed: false` and an eval fails if anyone flips it without review (release gate P6-5). The brand tagline "Schools. People. Progress." is **never translated** without brand approval.
4. **Web: the language is in the URL.** English at `/`, others at `/ur`, `/hi`, ... (`localePrefix: as-needed`); every language is statically prerendered by `generateStaticParams`. Reason: the apps use `cacheComponents`, where reading a cookie in the root layout would block the route (verified in the Next docs bundled in `node_modules`), and the public site needs per-language URLs for SEO. `next-intl` handles routing and messages; the locale proxy is `src/proxy.ts` (Next 16 renamed middleware to proxy).
5. **Flutter: explicit locale, fallback delegates.** Flutter has no Material/Widgets/Cupertino localizations for Kashmiri, Dogri or Sindhi (verified in the SDK sources), so a stock `MaterialApp` cannot load them. `oruLocalizationsDelegates` map those languages to a fallback (Kashmiri/Sindhi to Urdu, Dogri to Hindi, English if a library lacks even that). Flutter's own RTL list also lacks Kashmiri, so `OruLocales.textDirectionOf` is authoritative and `oruAppBuilder` applies it.
6. **Fonts (all bundled in Flutter, lazy self-hosted on web):** Noto Sans (Latin) plus one Noto family per script. **Urdu and Kashmiri use Noto Nastaliq Urdu** (the script style local readers expect); Sindhi, Pashto, Persian and Arabic use Noto Naskh Arabic. Cost: **4.44 MiB per Flutter app** (4,653,724 bytes; 12 families, 26 files), of which Nastaliq is 1.89 MiB; switching `ur`/`ks` to Naskh in `locales.json` (`"font": "Arabic"`; Naskh is 0.28 MiB) saves 1.61 MiB (to 2.83 MiB) if app size becomes a problem. A size budget (5 MiB) is enforced by an eval. Weights: 400/600/700 for Latin and Devanagari, 400/700 for the rest (Flutter resolves 600 to 700).
7. **Line heights:** tall scripts need more room than the design values (13-28 px type at ratios 1.29-1.57). Per-script minimums (`minLineHeight`: Nastaliq 2.0, Telugu/Kannada/Malayalam/Arabic 1.7, others 1.5-1.6) **only raise** line heights. These are starting values to be confirmed visually with native readers.
8. **Numerals:** product numbers (fees, marks, dates) use **Latin digits 0-9** in every language for v1 (money must be unambiguous); native digits are a later, per-school option. Currency grouping follows the school locale (default `en-IN`: Rs 1,82,40,000).
9. **Messages** are ICU, authored once in `packages/i18n/messages/en.json` (with translator descriptions) and generated into ARB (Flutter), TypeScript (web) and CSS/Dart/font loaders. Plural branches must use `{count}`, **not** `#` (Flutter's gen-l10n does not substitute `#`; found by test).
10. **No physical directions.** Use logical properties and APIs (`ms-`/`me-`/`ps-`/`pe-`/`text-start`, `EdgeInsetsDirectional`, `AlignmentDirectional`, `TextAlign.start`); `check:drift` rejects `ml-4`, `text-left`, `margin-left`, `EdgeInsets.only(left:)` and similar. Directional icons (chevrons, back arrows) must mirror in RTL; `↑ ✓ ↻` are not in Noto Sans and are never rendered as text.

## Verified, not assumed
All 19 languages load in a real `MaterialApp` (test per language); a rendering of every script with the bundled fonts was inspected (no missing glyphs, correct shaping, RTL alignment); the production web build serves `/ur` as `<html lang="ur" dir="rtl">` and `/` as English even when the browser asks for Urdu; font glyph coverage per language is computed against the shipped files (`provenance.json`).

## Not done yet (tracked in `implementation_plan.md`)
Language picker UI and persistence (user preference, school default); translating beyond the 32 starter keys; localized push/SMS templates; Urdu/Kashmiri mixed-direction edge cases in tables and forms; native-speaker review of Hindi and Urdu; visual tuning of line heights; Hebrew/other RTL scripts (direction logic is generic, fonts are not bundled).
