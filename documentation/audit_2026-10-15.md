# Repo Audit — 2026-10-15

Baseline snapshot used to set up guidelines, evals and drift checks. Reproduce with `npm run check:drift`.

## State of the repo
Docs-heavy, code-light. Three stock `create-next-app` scaffolds, a Data Connect schema (12 tables) with one connector (23 operations), design tokens package (empty), no API gateway, no Flutter apps, no tests, no CI, not a git repo at the root.

## Design system review (added same day)

Scope: `design-system/` (README, `tokens.json`, `tokens.css`, 18 component READMEs, `index.d.ts`, `bundle.js`, previews) and `brand-assets/` (guidelines, 31 SVGs, PNG icons, templates). The design system is **strong and internally consistent**; the issues below are mostly integration gaps with the rest of the project.

### Verified (by computation, not by reading)
- All contrast claims hold: text pairs ≥ 4.5:1 and controls/focus/chart ≥ 3:1 in **both** themes; app-icon ratios match their stated values (11.4, 6.3, 5.4, 4.8, 9.4; driver yellow with white = 1.84). `indigo-500` on white = 4.47 — correctly marked "never text". Now enforced by `evals/design-tokens.test.mjs`.
- `tokens.css` is identical to `tokens.json` (0 mismatches over every token, both themes). Enforced by drift rule `tokens-parity`.
- `Brand.md` and `Brand-guidelines.md` are byte-identical (duplicate). Enforced by drift rule `brand-mirror`.
- Hex palette in the older `DesignDoc.md` §13 matches the tokens; the older `design_system_spec.md` did not (see D8).
